## Confirmed runtime behavior

1. The user plugin registers for both `s_login` and `s_update`; both call the same called-number check.
2. Redirection only runs when `defs.FASTDIAL_PREFIX` is non-empty and `called_number` starts with that prefix.
3. The suffix is converted to an integer. A non-integer suffix raises the source's `INVALID_FAST_DIAL_INDEX` error. The parsed integer indexes the stored ten-entry list; an out-of-range index raises the same error. Preserve Python's source behavior rather than adding an assumed range check.
4. The selected destination replaces `ras_msg["called_number"]`, and the RAS implementation's `setRedirectNumber(reply_packet, destination)` is called.
5. The plugin stores the chosen index as `instance_info["attrs"]["fast_dial_index"]`. This is a session-instance side effect, not merely an attribute mutation.
6. The comment in the source says the called number is set later by the charge plugin; the runtime redirect-number reply is still set immediately by the fast-dial plugin.
7. The native actions manager exposes `addDestinationToFastDial(voip_username, destination, index)` and `getFastDialDestination(voip_username, index)`. Adding a destination requires digit-only destination text and index 0–9; it updates one slot and delegates to the native user action manager using the `system` administrator. A missing fast_dial attribute is treated as ten empty entries. A missing/unset lookup returns an empty string.

## ATD boundary and remaining work

The current ATD `fast_dial` API slice implements source-shaped ten-entry validation, comma-joined `user_attrs` persistence, deletion, and the source-specific suppression of native user-audit writes on both change and delete. The runtime plugin, per-instance `fast_dial_index` side effect, called-number rewrite, RAS redirect reply, and native actions-manager/XML-RPC compatibility are **not implemented**.

Do not claim runtime compatibility until the RAS message model exposes the source-required called-number mutation and redirect-reply contract, the session-instance metadata has an authoritative lifecycle, and tests cover prefix disabled/nonmatching, malformed suffix, empty destination, index boundaries, reply redirect, login/update paths, and concurrent destination updates. Do not implement this as a generic Access-Accept attribute: A1.24 mutates the VoIP/RAS message and calls the RAS provider's redirect method.
