## Confirmed runtime behavior

1. The user plugin registers for both `s_login` and `s_update`; both call the same called-number check.
2. Redirection only runs when `defs.FASTDIAL_PREFIX` is non-empty and `called_number` starts with that prefix.
3. The suffix is converted to an integer. A non-integer suffix raises the source's `INVALID_FAST_DIAL_INDEX` error. The parsed integer indexes the stored ten-entry list; an out-of-range index raises the same error. Preserve Python's source behavior rather than adding an assumed range check.
4. The selected destination replaces `ras_msg["called_number"]`, and the RAS implementation's `setRedirectNumber(reply_packet, destination)` is called.
5. The plugin stores the chosen index as `instance_info["attrs"]["fast_dial_index"]`. This is a session-instance side effect, not merely an attribute mutation.
6. The comment in the source says the called number is set later by the charge plugin; the runtime redirect-number reply is still set immediately by the fast-dial plugin.
7. The native actions manager exposes `addDestinationToFastDial(voip_username, destination, index)` and `getFastDialDestination(voip_username, index)`. Adding a destination requires digit-only destination text and index 0–9; it updates one slot and delegates to the native user action manager using the `system` administrator. A missing fast_dial attribute is treated as ten empty entries. A missing/unset lookup returns an empty string.

## ATD boundary and remaining work

The current ATD `fast_dial` API slice implements source-shaped ten-entry validation, comma-joined `user_attrs` persistence, deletion, and the source-specific suppression of native user-audit writes on both change and delete. The runtime plugin, per-instance `fast_dial_index` side effect, called-number rewrite, RAS redirect reply, and native actions-manager/XML-RPC compatibility are **not implemented**.

Do not claim runtime compatibility until the RAS message model exposes the source-required called-number mutation and redirect-reply contract, the session-instance metadata has an authoritative lifecycle, and tests cover prefix disabled/nonmatching, malformed suffix, empty destination, index boundaries, reply redirect, login/update paths, and concurrent destination updates. Do not implement this as a generic Access-Accept attribute: A1.24 mutates the VoIP/RAS message and calls the RAS provider's redirect method.

## ATD action-manager increment — 2026-10-12

Implemented a source-shaped persistence adapter at `src/atd_radius/infrastructure/fast_dial_actions.py` and admin API operations under `/api/v1/users/voip/{voip_username}/fast-dial/{index}`:

- GET resolves the native VoIP username and returns an empty destination for unset/out-of-range slots; Python negative-index behavior is retained where applicable.
- PUT enforces the native digits-only destination and 0–9 write index checks, locks the owning user row to serialize concurrent slot changes, updates one of ten `fast_dial` entries in `user_attrs`, and writes a separate operational audit.

Regression tests cover slot defaults, single-slot mutation, input validation, index semantics, row locking, permission denial and operational audit.

This completes the **admin/API action-manager slice**, not the VoIP runtime plugin. Production `s_login`/`s_update` called-number rewriting, RAS redirect-reply integration, and the per-instance `fast_dial_index` lifecycle remain open; do not claim complete fast-dial parity until those are connected to an authoritative VoIP/RAS message lifecycle and tested.

## Direct content review: runtime call chain — 2026-10-12

The archive was read directly for `IBSng/core/user/plugins/fast_dial.py`, `IBSng/core/user/ras_msg_dispatcher.py`, `IBSng/core/user/user.py`, `IBSng/core/user/user_plugin.py`, and `IBSng/core/ras/msgs.py`. The plugin is registered by `init()` as a user plugin and implements `s_login` and `s_update`; each invokes the same called-number rewrite. The dispatcher routes messages to user lifecycle operations, while the plugin hook manager dispatches the corresponding source hook. On a matching prefix, the plugin converts the suffix with `int()`, uses Python list indexing (so negative indexes are accepted at runtime), records `fast_dial_index` in the exact user instance's `instance_info["attrs"]`, mutates `ras_msg["called_number"]`, and calls `ras_msg.getRasObj().setRedirectNumber(ras_msg.getReplyPacket(), fast_dial_entry)`. The source comment explicitly says the called number will later be set by the charge plugin. This is not equivalent to setting a generic RADIUS Access-Accept attribute.

The source actions manager is a separate path: write indexes must be integers in 0–9 and destinations must be digits; a missing fast-dial attribute is represented as ten empty slots. The read method catches failures and returns an empty string. These runtime and management semantics must remain distinct. ATD currently implements the management API and a pure domain helper, but its production `RadiusRuntimeHandler` only handles RADIUS packets and has no `RasMsg`/VoIP login-update lifecycle or per-instance fast-dial state. Therefore the production redirect path remains unimplemented; no complete fast-dial parity claim is allowed. The next source-backed implementation must establish the VoIP/RAS message lifecycle and provider redirect-reply contract before wiring the helper.
