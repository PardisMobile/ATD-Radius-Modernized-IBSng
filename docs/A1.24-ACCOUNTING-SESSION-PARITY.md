# A1.24 Accounting / Session Lifecycle Audit

Source: `Source of Truth/IBSng-A1.24.tar.bz2`.

## Source-confirmed behavior

- The RADIUS server accepts authentication and accounting packets and dispatches them asynchronously.
- Duplicate detection key is `(source IP, source port, packet id, packet code)`; completed duplicates receive the cached response.
- Accounting is delegated to the RAS implementation through `_handleRadAcctPacket`.
- RAS implementations translate `Acct-Status-Type` into A1.24 actions such as `INTERNET_UPDATE` and `INTERNET_STOP`.
- MikroTik handles Start, Stop and Alive; Start initializes online accounting state, Alive calculates byte deltas/rates, and Stop terminates the session.
- Connection history is persisted in `connection_log` plus `connection_log_details`. The canonical schema uses one detail row per `(connection_log_id, name)`.
- `insert_connection_log` stores user, credit, login/logout timestamps, success state, service type (internet/voip), RAS id and named details.
- On normal Internet logout, A1.24 calls `calcInstanceCreditUsage(instance, True)`; the resulting `used_credit` is committed through `change_user_credit(user_id, -used_credit)` and the same value is passed to `logConnectionQuery`.
- For Internet charge rules, the source calculation is time charge `cpm * elapsed_seconds / 60` plus transfer charge `cpk * transfer_octets / 1024.0`.
- The calculated usage is instance-aware: usage accumulated before the current interval is preserved in `credit_prev_usage_instance`, while multi-instance total usage also includes `credit_prev_usage`.
- VoIP follows the same instance-credit/commit/connection-log pattern, with its own `VoIPCharge` calculation and special handling for `no_commit` / minimum-duration calls.
- A1.24 skips connection-history insertion when the effective RAS message has `no_connection_log`.

## ATD implementation

ATD has:
- Start / Stop / Alive accounting state;
- octet delta calculation;
- the A1.24 session action vocabulary;
- conversion of RADIUS accounting attributes into typed accounting events;
- native `connection_log` persistence;
- source-derived `no_connection_log` suppression;
- a native user-credit repository using the A1.24 `users.credit` column and `change_user_credit()` function.

## Remaining source-parity gap

The runtime Charge integration is now implemented in ATD. The session state carries the active charge/rule, rule start time, per-rule IN/OUT baselines and accumulated per-instance charge; Stop settles credit and persists the same `credit_used` to `connection_log`, while `no_commit` skips settlement.

The implementation intentionally follows the A1.24 Charge state model rather than treating raw RADIUS deltas as the billing authority: effective-rule selection, rule timing, rule-start transfer baselines, rule-transition accumulation and per-instance state are represented explicitly.

Source verification is now complete for the Internet charge rule hook path: A1.24 `InternetChargeRule.start()` calls the base rule start, then stores `user_obj.getTypeObj().getInOutBytes(instance)` into `charge_info.rule_start_inout[instance-1]`; `calcRuleInOutUsage()` subtracts that per-instance baseline and `calcRuleTransferUsage()` sums the IN/OUT deltas. `InternetChargeRule.end()` calls the base rule end and removes the applicable bandwidth limits. The source trace was obtained from a successful temporary GitHub Actions extraction of the canonical archive; the temporary workflow was removed afterward.

ATD mirrors that state with per-session charge-rule start time and IN/OUT baselines. The remaining architectural validation is transaction ownership: `build_native_radius_runtime()` intentionally accepts a caller-owned psycopg connection, while `infrastructure.db.connection()` provides the short-lived transaction boundary. Its context manager commits on normal exit and rolls back when an exception escapes. The UDP transport itself does not own a DB connection, so production wiring must keep accounting application plus persistence on the same connection/context; the runtime builder already composes them over the same supplied connection.

Status: **source-traced and runtime-integrated; transaction ownership is documented as an integration requirement, not an unverified billing-source gap.**
