## Source paths traced

- `IBSng/core/bandwidth_limit/bw_actions.py`: `getTree`, `getSubTree`, `addInterface`, `addNode`, `addLeaf`, `addLeafService`, deletion and update handlers.
- `IBSng/core/bandwidth_limit/interface.py`: `getInfo`, root-node relationship and `createTree`/root-qdisc setup.
- `IBSng/core/bandwidth_limit/node.py`: parent/child registration, node info and traffic-control subtree operations.

- `IBSng/core/admin/perms/CHANGE_BANDWIDTH_MANAGER.py`: registered permission `CHANGE BANDWIDTH MANAGER`, dependent on `CHANGE CHARGE`.

## Verified source behavior

- `getTree(interface_name)` resolves the interface and returns a recursive subtree. Each node is represented as `[node_id, child_nodes, child_leaf_names]`; leaf entries are names, not leaf IDs.
- The interface record exposes `interface_id`, `interface_name`, and `comment`. A node exposes its ID, interface ID, parent ID, rate and ceil. The root node is the node with no parent for that interface.
- Native mutations have operational side effects. Adding an interface creates a root node and a root HTB qdisc; adding/updating/deleting nodes and leaves calls loader registration/reload and traffic-control operations. Leaf deletion is blocked when services, charge rules or static-IP assignments still reference it. Node deletion is blocked when it has child nodes/leaves; root deletion requires an explicit flag.
- Rate validation requires positive integer limits no greater than 1,048,576 kbit/s for the native fields checked by `__checkLimitKbits`. Service filters have protocol/type-specific validation. These write-side contracts are not implemented by the read-only increment.
