# A1.24 Verified / Frozen Work Register

This file is the durable freeze ledger for ATD Radius Modernized IBSng. It exists to prevent already source-traced, implemented, and regression-tested behavior from being reimplemented or casually changed in later batches.

## Rules for all future work

1. **Check this register before changing behavior.** Also inspect the canonical archive `Source of Truth/IBSng-A1.24.tar.bz2` (SHA-256 `c7117a6a2fd252aa9b8149a1ee6606f9320888da347ee4f839614bb9349d18a`) whenever the change claims IBSng compatibility.
2. A freeze is scoped to the exact behavior below—not to the entire feature family, module, or runtime.
3. A frozen slice is changed only when a new reproducible defect, source discrepancy, security issue, or necessary integration side effect is demonstrated. First add the evidence and rationale here or to the corresponding audit record; then make the smallest correction and add a regression test.
4. Do not infer completion from similar names, documentation alone, or green CI. Record source location, test coverage, validation checkpoint, and unverified boundaries.
5. Keep work directly on `main`; do not open a PR as the default integration process.
6. When a behavior is newly verified, append it here in the same batch that implements/tests it. Update the status and compatibility ledger too when their claims are affected.

## Frozen slices

### FRZ-A124-EXPIRY-001 — Absolute/relative expiry boundary semantics
- **Source:** `IBSng/core/user/plugins/abs_exp.py::AbsExpDate.__isAbsExpired`; `IBSng/core/user/plugins/rel_exp.py::RelExpDate.__isRelExpired`.
- **Verified semantics:** absolute expiry is strict (`deadline < now`); relative expiry is inclusive (`first_login + duration <= now`). Exact absolute expiry is not rejected at that instant; the active-session scheduler rechecks after its minimum interval rather than silently dropping the timer. Exact relative expiry is due.
- **Regression scope:** exact boundaries, equal-deadline precedence, and scheduler continuation.
- **Validation reference:** checkpoint `300a3799589b51f7b8918fed7537a8a063aba887`; full CI run [40798723019](https://github.com/PardisMobile/ATD-Radius-Modernized-IBSng/actions/runs/40798723019), Python-only [40798723305](https://github.com/PardisMobile/ATD-Radius-Modernized-IBSng/actions/runs/40798723305).
- **Freeze boundary:** do not redo or alter these exact comparison/scheduler-boundary behaviors. Broader expiry lifecycle parity remains open.

### FRZ-A124-PERIODIC-002 — Daily periodic reset catch-up equality behavior
- **Source:** `IBSng/core/user/plugins/periodic_accounting.py::BasePeriodicAccounting._calcNextReset` and due hook.
- **Verified semantics:** due check is `next_reset <= now`; daily calculation starts from saved `next_reset + interval` and advances only while candidate `< now`. A delayed callback exactly at a missed boundary may calculate a reset equal to now; a subsequent due call advances again from that saved boundary.
- **Regression scope:** delayed exact-boundary catch-up, repeated call at same epoch, and source-shaped strict candidate comparison.
- **Validation reference:** implementation `64d5f21f629e0ab849c18d70949ce04d06fea3d1`, regression `f12f18f331aae60e82404ad3454f8bfabbdca5a6`, documentation correction `36ff457f9e82017ca5589e32fef6ab26b8efa317`, final comment clarification `32d46f52620269f367edf2150683feb5851da709`. CI and Python workflows on the comment clarification both succeeded.
- **Freeze boundary:** do not revert to “always strictly future” catch-up or reimplement this arithmetic. This is only the verified daily catch-up boundary; full periodic plugin parity is not frozen/complete.

### FRZ-A124-FIRST-LOGIN-003 — First-login persistence after accepted authentication
- **Source:** A1.24 user-plugin first-login lifecycle (recorded in the expiry/periodic batch source audit).
- **Verified semantics:** candidate first-login value is committed only after successful Access-Accept and is not renewed on later logins.
- **Regression scope:** integrated dispatcher reject/accept and response-attribute privacy.
- **Validation reference:** checkpoint `300a3799589b51f7b8918fed7537a8a063aba887`; full CI run [40798723019](https://github.com/PardisMobile/ATD-Radius-Modernized-IBSng/actions/runs/40798723019).
- **Freeze boundary:** do not reimplement the accepted-login commit boundary. Remaining plugin hook and broader lifecycle parity stays open.

### FRZ-A124-AUTH-WIRE-004 — Native CHAP/MS-CHAP and MPPE packet/codec slice
- **Source:** canonical A1.24 RADIUS authentication and password/key derivation behavior; implementation files and tests are maintained in the native authentication pipeline.
- **Verified semantics:** CHAP uses the packet authenticator; MS-CHAPv1 MPPE output; MS-CHAPv2 success and Send/Recv key derivation; malformed or incorrect responses do not leak keys; MS-CHAPv2 response normalization supports bytes, bytearray, and hexadecimal text; native request/dispatcher/response codec round-trip preserves the response identifier and encrypted MPPE keys with the original request authenticator.
- **Regression scope:** native local pipeline and codec only.
- **Validation reference:** checkpoint `20e9f8cbe8d59b54bec9d337e071d9cd59d486d1`; full CI Python 3.11/3.12, 1,140 passed each, 2 warnings.
- **Freeze boundary:** do not redo this local wire/codec implementation. **Live NAS/supplicant interoperability, provider-specific behavior, and complete A1.24 authentication/plugin parity are explicitly not frozen as complete.**
