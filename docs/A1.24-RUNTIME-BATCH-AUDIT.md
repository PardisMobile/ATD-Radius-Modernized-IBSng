# A1.24 Runtime Batch Audit

This batch was checked directly against the canonical A1.24 source archive.

## Confirmed runtime architecture

### User plugin manager
A1.24 registers plugins into ten numeric priority buckets (0..9). Lower numbers execute first; registration order is preserved inside a priority bucket. Hooks include:

- USER_INIT
- USER_LOGIN
- USER_LOGOUT
- USER_COMMIT
- USER_CAN_STAY_ONLINE
- USER_RELOAD
- UPDATE

ATD now has an explicit `PluginSpec(priority, name, policy)` and deterministic priority ordering.

### Login/session policies
Source-confirmed behavior now represented in ATD:
- absolute expiry rejects expired login and schedules remaining lifetime while online
- relative expiry initializes `first_login` at login time, commits it, and computes expiry from first_login + rel_exp_date
- multi-login defaults to 1
- RAS-level multi-login permission can reject a second instance
- session_timeout and idle_timeout become RADIUS reply attributes

### IP pools
A1.24 uses an ordered free/used container:
- allocation takes the first free IP
- explicit IP use removes it from free and moves it to used
- release removes it from used and returns it to free when the IP still belongs to the pool
- allocated RADIUS replies use Framed-IP-Address and 255.255.255.255 netmask

ATD now exposes these lifecycle operations while retaining its previous allocator API.

### RADIUS duplicate requests
A1.24 duplicate identity is based on source IP, source port, packet identifier and packet code. Finished duplicates reuse the cached response. ATD now has an explicit request-cache primitive for this contract.

### Online sessions
A1.24 keeps per-user online instances, processes updates, recalculates the next user event, invokes canStayOnline, and can terminate instances returned by the policy result. ATD now has the session registry/delta primitives; the live RADIUS-to-session adapter remains pending.

### Connection history
A1.24 persists connection_log and connection_log_details. ATD now has a repository contract preserving that native logical record.

## Fixed checkpoints for future chats

The source-derived findings in this document are established checkpoints, not open discovery tasks. In particular, MultiLogin/attribute inheritance, duplicate identity, IP-pool runtime semantics and the native connection-log shape have already been traced. Future work should continue from the unresolved items below rather than repeating those traces.

## Explicitly not claimed as Verified

The above is source-mapped and covered by domain tests where stated. It is not yet end-to-end parity. Remaining work includes live UDP RADIUS integration, PostgreSQL repositories, all plugin hooks, all RAS implementations, accounting persistence, CoA/Disconnect, authentication protocol coverage, and migration verification.
