## Login restriction runtime increment — 2026-10-25

The live Access-Request pipeline now enforces A1.24 `limit_caller_id`, `limit_mac` and `limit_station_ip` attributes after provider-specific source normalization. Caller ID patterns use the source's regex-search semantics and honor `limit_caller_id_allow_not_defined`; a missing caller ID is denied unless the flag is exactly `1`. The normalized fields currently follow the inspected native RAS handlers:

- ChilliSpot: `Calling-Station-Id → mac`
- MikroTik: Ethernet/Wireless-802.11 → `mac`; Virtual → `station_ip`; numeric NAS-Port-Type values are normalized to the same source labels.
- PPPD: `Calling-Station-Id → station_ip` (the optional legacy external MAC-discovery script is not invoked by this pure admission path).
- BSAE: the first 12 Calling-Station-Id characters are formatted as six colon-separated octets for `mac`.
- Cisco, GnuGk, MVTS and Quintum Tenor: `Calling-Station-Id → caller_id`.

The policies preserve the source's conditional behavior: a restriction is evaluated only when the configured user attribute and the corresponding RAS-derived field are both present. Station-IP values support individual addresses and IP/netmask ranges; invalid input or malformed stored ranges reject rather than silently bypass the restriction. Unit, provider-normalization, access-context and live dispatcher tests cover this batch.

This closes these three login hooks only for the provider mappings above. It does not complete every user plugin's login/update/commit/logout/canStayOnline lifecycle, remaining caller-ID/VoIP behavior, persistent-LAN workflows, or plugin side effects. Latest full PostgreSQL CI is still pending for the newest code checkpoint.


## Periodic-accounting arithmetic foundation — 2026-10-26

Added domain/periodic_accounting.py with source-aligned time/traffic quota arithmetic, per-instance baselines, accumulated usage, logout commits, daily reset advancement, active-instance rebasing at reset, and remaining-time estimates. Gregorian/Jalali month boundaries are deliberately delegated to an exact source-compatible calendar helper rather than approximated. Regression tests cover baseline deltas, quota exhaustion, one-time logout commit, reset behavior and invalid configurations.

**Not yet runtime parity:** the new engine is not wired into the live plugin hook lifecycle or persistent user-attribute updates. Until those integrations and source-compatible month helpers are completed, periodic accounting remains an open core blocker.
