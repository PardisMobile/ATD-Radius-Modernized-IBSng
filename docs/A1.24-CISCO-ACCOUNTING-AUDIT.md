# A1.24 Cisco Accounting service and identity audit

Date: 2026-10-17  
Canonical source: `Source of Truth/IBSng-A1.24.tar.bz2`  
Source file inspected: `IBSng/core/ras/rases/cisco.py`

## Direct source findings

- `CiscoRas.__isInternetPacket(pkt)` returns true only when `Framed-Protocol` exists and its first value is `PPP`.
- `handleRadAcctPacket(ras_msg)` selects the Internet or VoIP accounting branch from that discriminator for `Start`, `Stop`, and `Alive`.
- Internet identity is `port`: `__addInternetUniqueIDToRasMsg` sets `unique_id="port"` and derives the port from `Cisco-NAS-Port` or `NAS-Port-Type + NAS-Port`.
- VoIP identity is `h323_conf_id`: `__addVoIPUniqueIdToRasMsg` reads the H.323 conference ID.
- VoIP Start only creates the native VoIP update action for `H323-call-type == "VoIP"` and `H323-call-origin == "originate"`.
- VoIP Stop handles that same originate leg; a `Telephony/answer` stop is handled only if its H.323 ID is present in the RAS's pre-authentication ID list.
- VoIP Alive updates Cisco's in-memory online tracker for a `VoIP/originate` leg; the source branch does not dispatch a normal charge-update action for it.

## ATD changes in this checkpoint

- `provider_service_for_accounting()` now applies the exact Cisco `Framed-Protocol == PPP` discriminator while retaining the source-derived default for other RAS types.
- Live Accounting resolves Cisco VoIP sessions from the H.323 call ID, not the Internet port or generic Accounting session ID.
- Restart recovery applies the same service-aware identity selection, keeping live and recovered session keys consistent.
- `event_from_attributes()` normalizes list/tuple representations to their first scalar value for status, identity, IP, counters, and persisted attributes.
- Regression coverage exists in `tests/domain/test_ras_provider.py`, `tests/domain/test_accounting_lifecycle.py`, and `tests/application/test_radius_runtime.py`.

## Explicit remaining parity gaps

This checkpoint implements service selection and identity, **not the entire Cisco RAS state machine**. The ATD runtime still needs a source-derived provider disposition layer to enforce Cisco's H.323 call-type/origin conditions before applying Start/Stop, reproduce the pre-authentication H.323 ID list for the special `Telephony/answer` Stop branch, and keep Cisco VoIP Alive updates separate from charge lifecycle events. Cisco SNMP/RSH termination and full end-to-end device interoperability also remain incomplete. Do not mark Cisco RAS parity complete from this increment alone.

## Cisco VoIP call-leg action gating — 2026-10-17

Implemented the source-defined Cisco VoIP action boundary for the lifecycle path: Start/Stop only enter normal user accounting for `H323-call-type == VoIP` and `H323-call-origin == originate`. Cisco VoIP Alive is not sent through charge/session lifecycle because A1.24 only refreshes the RAS's local online tracker in that branch. The special `Telephony/answer` Stop path is currently rejected because ATD has not yet implemented the source's pre-auth H.323 ID list; it must not be treated as equivalent until that state is modeled. Regression tests cover accepted originate legs, ignored answer legs and Alive suppression.

## Cisco wire-form attribute normalization — 2026-10-17

A direct source comparison with VoIPRas.getH323AttrValue showed that Cisco H.323 values arrive in the Attribute-Name=value form and A1.24 strips that prefix before comparing call type/origin or using the conference ID. The provider resolver now normalizes that representation for H.323 identity and Cisco call-leg gating. Cisco Internet identity also now follows __getPortFromRadiusPacket: prefer Cisco-NAS-Port (including the source's Async-port extraction), otherwise concatenate NAS-Port-Type and NAS-Port. Regression tests cover wire-form values and both Internet port branches.


## Cisco VoIP Accounting username namespace — 2026-10-17

The canonical Cisco adapter splits the RADIUS User-Name into the native VoIP username and password using the configurable cisco_voip_username_length (default 8) before VOIP_UPDATE/VOIP_STOP user resolution. The live ATD Accounting path now applies that same source-derived split before looking up the user ID, while leaving Internet and non-Cisco usernames unchanged. Regression tests cover the default/configured prefix and the full runtime path.


## Cisco pre-auth H.323 ID list — 2026-10-17

Implemented the missing process-local authorization list from CiscoRas.voip_auth_h323ids. A successful Cisco VoIP Authorization Access-Accept (Called-Station-Id present) records the normalized H.323 conference ID. A normal VoIP/originate Accounting Start consumes that ID. A Telephony/answer Accounting Stop is accepted only if the conference ID is present in that list, matching the A1.24 source branch; IDs are intentionally not persisted across restart because the source list itself is in-memory.


## Cisco Accounting Alive semantics — 2026-10-17

Cisco's source dispatches Alive packets to its own online tracker only; it does not dispatch INTERNET_UPDATE or VOIP_UPDATE user accounting actions for them. The runtime now maintains process-local Cisco online metadata and short-circuits Alive before charge/session persistence. Internet Alive updates the matching port entry only when username matches; VoIP/originate Alive refreshes an existing H.323 entry. This mirrors the in-memory nature of the A1.24 tracker.


## Cisco session identity fail-closed parity — 2026-10-19

Cisco's source derives Internet identity only from Cisco-NAS-Port or NAS-Port-Type + NAS-Port, and VoIP identity only from H.323 conference ID. The provider resolver no longer substitutes Acct-Session-Id or the other service's identity when these source-required keys are absent. This makes live accounting and restart recovery skip unresolvable Cisco sessions rather than merge unrelated sessions.


The strict Cisco VoIP identity list intentionally excludes Acct-Session-Id, even though other VoIP provider profiles may use it as a fallback. This mirrors CiscoRas's direct H.323 conference-ID extraction.
