# Session State Audit

Date: 2026-10-10

## IBSng A1.24

`IBSng/core/user/online.py` maintains active state in memory in `OnlineUsers.user_onlines` and `ras_onlines`. `core/user/user_pool.py` coordinates user loading and the online flag. Connection history is not the same thing as current online state.

## ATD

- `src/atd_radius/domain/radius_runtime.py::SessionRegistry` keeps live sessions in process memory and exposes `active_for_user(user_id)`.
- `src/atd_radius/domain/accounting_session.py::AccountingSessionService.apply` updates registry state and calls persistence separately.
- `src/atd_radius/application/radius_runtime.py::RadiusRuntimeHandler` routes Accounting-Request events through that service; Disconnect-Request also works with the registry.
- `src/atd_radius/infrastructure/accounting_persistence.py::NativeAccountingPersistence` writes connection history; it is not the authoritative live registry.

## Finding

ATD has an in-memory active-session registry, but it is process-local. The current API does not expose a reservation/lock coordinating Accounting Start with administrative user operations. Do not use `connection_log.logout_time IS NULL` as a substitute for the live registry.

## Required before deletion support

1. Confirm runtime process/worker topology and whether registry state is shared.
2. Define a concurrency-safe reservation coordinating Accounting Start, Stop and Disconnect with deletion.
3. Define stale-session/restart behavior.
4. Add tests for concurrent Start/Stop and multiple runtime instances.

Status: audit only; no user-deletion endpoint has been added.


## Updated concurrency boundary — 2026-10-12

The earlier finding that Accounting Start and persistence mutate state without an operation-wide lock has been partly addressed: `SessionRegistry` now exposes a re-entrant synchronization boundary and `RadiusRuntimeHandler` holds it across Accounting-Request dispatch, identity/provider resolution, session application, persistence and IP-pool Start/Stop side effects. Full CI on implementation/test HEAD `f97af48b94204ac2e7d6065d522c29d2583dc76e` passed 694 tests on Python 3.11 and 3.12 (2 warnings each).

This does not close the source-specific gap in the original finding. A1.24's `LoadedUser.online_flag` is reserved before login succeeds and remains true until the last RAS instance logs out. ATD still derives active state from RADIUS accounting and therefore cannot safely represent the Access-Accept-to-Accounting-Start interval or login-in-progress reservation; process restart/multiple workers also remain unresolved. No user-deletion or admin disconnect endpoint should be inferred safe from the lock alone.
