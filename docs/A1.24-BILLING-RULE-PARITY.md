# A1.24 Billing Rule Parity Audit

Canonical source: Source of Truth/IBSng-A1.24.tar.bz2

## Implemented boundary

ATD now models the A1.24 charge-rule specificity used by `ChargeRule.__calcPriority()`:

- RAS-specific: priority 2
- port-specific: priority 1
- both: priority 3
- both wildcard: priority 0

Rules are filtered by day-of-week, time interval, RAS and port, then the highest-priority applicable rule is selected. Equal-priority rules retain loader/input order, matching the A1.24 loop which replaces the selected rule only when `rule.priority > max_priority`.

Internet pricing follows the A1.24 runtime formula:

- CPM: `cpm * seconds / 60`
- CPK: `cpk * octets / 1024`
- total = time component + transfer component

The source schema is also preserved conceptually: `charge_rules` is the parent, with `internet_charge_rules` and `voip_charge_rules` inheriting from it, while ports and days are separate child tables.

## Source correction — empty port set is not wildcard

A1.24 `core/charge/charge_rule.py::anytimeAppliable` applies a rule only when the active port is in the rule's configured port set or the explicit `_ALL_` marker is present. An empty `charge_rule_ports` result does **not** mean all ports. The domain selector had treated an empty set as a wildcard; this was corrected, and billing fixtures now use explicit `_ALL_` where wildcard behavior is intended. Regression coverage asserts that an empty port list yields no applicable rule. This is a source-backed behavior correction, not a protocol/authentication change.

## Source-accurate empty-port persistence — 2026-10-12

A deeper trace of `ChargeActions.__addChargeRulePortsQuery` found that an empty submitted port list is stored as one `charge_rule_ports.ras_port = NULL` row, not as zero child rows. The loader returns that SQL NULL unchanged, and `ChargeRule.anytimeAppliable` still does not treat it as a wildcard; only a literal port match or `_ALL_` applies. The VoIP adapter now preserves this exact storage/mapping behavior and overlap checks distinguish SQL NULL from the string `"None"`.
