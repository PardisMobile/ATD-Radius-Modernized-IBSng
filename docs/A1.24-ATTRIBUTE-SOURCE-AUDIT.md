# A1.24 Attribute Source Audit

This audit corrects an earlier assumption in the ATD migration notes.

## Confirmed from the available A1.24 source extraction

`user_attrs` and `group_attrs` are real attribute stores using `attr_name` and `attr_value`.

The A1.24 group loader reads `group_attrs` by `group_id` and converts rows into `{attr_name: attr_value}`. The group API exposes `updateGroupAttrs`, accepting attributes to update and attributes to delete. This means update/delete semantics are part of the compatibility contract, not just persistence.

The A1.24 web interface also uses a generic attribute-update helper and plugin update methods. User attributes include operational fields such as normal/VoIP credentials, IP-pool assignment, RADIUS attributes, bandwidth-related settings, persistent LAN settings, caller-ID settings, session limits and other plugin-defined values.

## `ras_attrs`

The current indexed A1.24 extraction available to the project does **not** provide enough direct evidence to certify a table named `ras_attrs` or its columns. Earlier migration notes treated `ras_attrs` as confirmed; that was premature and is withdrawn.

Therefore ATD must not create a PostgreSQL mapping for `ras_attrs` until the A1.24 `tables.sql` definition and its Python consumers are directly verified.

## Migration rule

A source object is considered confirmed only when both are available:

1. its database definition, and
2. at least one real source consumer/update path.

Until then its migration status remains `Unverified`, and no guessed schema is permitted.

## Next target

Continue source-first extraction for RAS configuration and attributes, then update the ATD schema manifest only from verified A1.24 definitions.
