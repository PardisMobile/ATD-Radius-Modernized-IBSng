## Source-derived runtime distinctions

### Internet RAS providers
The following providers maintain provider-specific online/accounting state and map RADIUS packets into the generic A1.24 user/session attributes rather than merely forwarding raw RADIUS counters:

- **MikroTik** — unique id is `port`; NAS-Port is used for the port key; Ethernet/Virtual/Wireless NAS-Port-Type changes IP-assignment behavior; Start initializes accounting state; Stop records final octets; Alive calculates byte-rate deltas and updates the online state.
- **BSAE** — unique id is `port`, port is User-Name, multi-login is explicitly false; Start/Stop/Alive are handled; IP learned from the Access-Accept is retained and reused for accounting; provider keeps per-port online and byte/rate state.
- **ChilliSpot** — unique id is `port`, port comes from NAS-Port, and `ip_assignment` is explicitly false; Start/Stop/Alive are handled, with Alive capable of re-online recovery; provider keeps online byte/rate state and has a provider-specific RADIUS Disconnect-Request path.
- **Cisco** — unique id is `port`; port normalization depends on Cisco/NAS port attributes; provider has separate internet and VoIP state, SNMP/RSH disconnect operations, and provider-specific byte/rate state; multi-login is explicitly false for the VoIP path.
- **Cisco VPDN** — uses Acct-Session-Id as the internet online key and has provider-specific interface discovery/kill behavior through RSH; online state has provider-specific stale-update handling.
- **PortMaster** — unique id is `port`, port comes from NAS-Port; provider uses SNMP for online/kill operations and keeps provider-side byte/rate state.
- **PortSlave** — unique id is `port`, port comes from NAS-Port; provider uses external launcher commands for listing/killing users and maintains provider-side accounting state.
- **Total Control** — unique id is `interface_index`, sourced from `USR-Interface-Index`; provider maps the interface index to NAS-Port and uses SNMP-derived IN/OUT counters.

### VoIP / telephony RAS providers

- **GnuGk** — VoIP-specific provider behavior; source-defined multi-login capability defaults false and is enabled only by the `gnugk_multiple_login` RAS attribute.
- **Asterisk** — VoIP handler exposes pre-authentication/authentication/authorization/call-end operations through the Asterisk manager; source-defined `asterisk_multi_login` defaults false and enables multi-login when nonzero.
- **Quintum Tenor** — VoIP provider keyed by `h323_conf_id`; maintains pre-auth usernames and online conference IDs; source sets multi-login false and `single_session_h323` true; Stop consumes the Quintum H323 disconnect cause.
- **MVTS** — VoIP provider keyed by `h323_conf_id`; source enables H323 authorization/accounting and remaining-time calculation, with provider-specific start/stop/alive processing.
- **SER** — SIP provider keyed by `call_id`; Start is tied to SIP INVITE and records the call id; Stop removes the call id; source maps Digest attributes and derives the called number from the SIP URI.
- **Cisco** — also contains a VoIP path keyed by H323 conference id in addition to its internet path.

### Persistent LAN

- **PersistentLanRas (plan.py)** is not a conventional RADIUS accounting provider. Source creates an internal `mac_ip` identity, marks the message `persistent_lan=True`, starts accounting, disables IP assignment, and maintains its own online/waiting lifecycle.

## Important parity consequence

The current ATD generic RADIUS runtime correctly models the common AAA/session/accounting boundary, but **full A1.24 RAS provider parity cannot be achieved by a single generic RAS boolean table**.

Provider-specific parity requires adapter behavior for:

1. identity/unique-id derivation;
2. input attribute extraction;
3. Start/Stop/Alive translation;
4. byte/rate counter semantics;
5. provider-specific IP assignment behavior;
6. provider-specific multi-login capability;
7. Disconnect/kill mechanisms;
8. VoIP/H323/SIP authentication and accounting;
9. provider-specific stale-online detection and update intervals;
10. provider-specific external SNMP/RSH/launcher integrations.

## Current ATD coverage

## Status

**Source audit: completed for the provider inventory and major provider-specific runtime distinctions.**

**Implementation parity: not complete.**

The common provider adapter facade is now implemented as `RASProviderRegistry`, exposing only already source-traced profile, identity, IP-assignment, status, disconnect-strategy and SIP helper behavior. BSAE identity parity now includes its source-defined exception where provider `port` is derived from `User-Name` rather than NAS-Port. This does not claim concrete provider side-effect parity. The next implementation step is to attach concrete source-derived adapters without weakening the generic RADIUS core.


### Direct canonical-source verification — BSAE — 2026-10-07
- The BSAE identity rule was re-verified directly from Source of Truth/IBSng-A1.24.tar.bz2, not inferred from this audit.
- Canonical source file: IBSng/core/ras/rases/bsae.py.
- In BSAERas.__addUniqueIDToRasMsg, A1.24 explicitly sets ras_msg["unique_id"]="port" and then sets ras_msg["port"]=ras_msg.getRequestPacket()["User-Name"][0].
- Therefore BSAE's provider port/identity key is User-Name, not NAS-Port or NAS-Port-Id.
- The ATD BSAE exception in provider_session_id() is source-verified and is covered by a regression test.
- The same source inspection confirms BSAE accepts PAP, CHAP, MS-CHAP and MS-CHAP2 response attributes in handleRadAuthPacket; this is source evidence, not an assumption from the generic provider table.
- Temporary source-inspection workflow was removed immediately after verification; no temporary workflow remains on the main branch.


### Direct canonical-source verification — Total Control / USR — 2026-10-07
- Canonical source files inspected directly from `Source of Truth/IBSng-A1.24.tar.bz2`: `IBSng/core/ras/rases/total_control.py`, `IBSng/radius_server/dictionary.usr`, `IBSng/radius_server/pyrad/dictionary.py`, and `IBSng/radius_server/pyrad/packet.py`.
- `total_control.py` sets `unique_id` to `interface_index` and derives it from `USR-Interface-Index`.
- `dictionary.usr` defines `USR-Interface-Index` as vendor `429`, code `0x9843`, type `integer`.
- Canonical `pyrad` encodes vendor attributes as `(vendor, attribute-code)` tuples. For vendor 429 specifically, it writes the vendor ID followed by a 32-bit attribute code and the raw value; decode performs the same 32-bit USR-specific parsing.
- ATD now contains the corresponding source-derived USR VSA definition and codec path, with a wire-level regression test.
- No one-byte VSA type was guessed for USR; the canonical 32-bit USR format is preserved.


### Direct canonical-source verification — ChilliSpot — 2026-10-07
- Canonical source file inspected directly: IBSng/core/ras/rases/chilli_spot.py.
- Source facts: unique_id is port; port is the string form of NAS-Port; ip_assignment is explicitly False; Authentication consumes PAP, CHAP, MS-CHAP and MS-CHAP2 inputs; accounting handles Start, Stop and Alive; Alive can trigger tryToReOnline when configured; disconnect uses a RADIUS Disconnect-Request sent to the configured disconnect IP/port with User-Name.
- ATD correction: ChilliSpot accounting statuses now include Alive. Regression coverage was added so the provider registry does not reject this source-defined status.


### Direct canonical-source verification — Cisco / Cisco VPDN — 2026-10-08
- Canonical files inspected directly from `Source of Truth/IBSng-A1.24.tar.bz2`: `IBSng/core/ras/rases/cisco.py` and `IBSng/core/ras/rases/cisco_vpdn.py`.
- Cisco Internet path: `unique_id="port"`; port is derived from `Cisco-NAS-Port` when present, otherwise from `NAS-Port-Type` + `NAS-Port`, with Async normalization.
- Cisco VoIP path: `unique_id="h323_conf_id"`; H323 conference ID is source-derived. VoIP explicitly sets `multi_login=False` and `single_session_h323=True`.
- Cisco authentication consumes User-Name plus PAP, CHAP, MS-CHAP, MS-CHAP2 and Calling-Station-Id; Internet auth returns Framed-User/PPP and INTERNET_AUTHENTICATE. VoIP has distinct authorization/pre-authentication/authentication actions.
- Cisco accounting explicitly handles Start/Stop/Alive for Internet and has separate VoIP Start/Stop/Alive handling. Internet Start/Stop also consume User-Name, Acct-Session-Id, Framed-IP-Address and Acct-Terminate-Cause as applicable.
- Cisco disconnect/kill behavior is provider-specific SNMP-or-RSH; the source contains both paths and the SNMP kill path uses the Cisco interface mapping.
- Cisco VPDN uses `unique_id="acct_session_id"`, consumes Acct-Session-Id and Cisco-NAS-Port during authentication, handles Start/Stop/Alive, and kills through RSH after discovering the user's interface. Its source-defined disconnect strategy is therefore `rsh-interface`.
- ATD correction: `provider_session_id(..., service="voip")` now returns Cisco's H323 conference identity while preserving Cisco Internet identity as `port`.
- Regression coverage was added for both Cisco Internet and Cisco VoIP identity paths.
- Source-audit branch/workflow was isolated and is not part of `main`.


### Direct canonical-source verification — PortMaster / PortSlave — 2026-10-08
- Canonical files inspected directly: `IBSng/core/ras/rases/portmaster.py` and `IBSng/core/ras/rases/portslave.py`.
- PortMaster: `unique_id="port"`; port is derived from NAS-Port. Auth consumes User-Name and optional User-Password, CHAP-Password, MS-CHAP-Response and MS-CHAP2-Response. Accounting maps Start to INTERNET_UPDATE, Stop to INTERNET_STOP, and the non-Start/non-Stop path to INTERNET_UPDATE; this includes A1.24 Alive handling. Disconnect/kill is SNMP and uses the provider port.
- PortMaster source-defined provider attributes include SNMP community `public`, timeout `10`, retries `3`; these are provider integration settings, not generic RADIUS behavior.
- PortSlave: `unique_id="port"`; port is derived from NAS-Port. Auth consumes the same PAP/CHAP/MS-CHAP/MS-CHAP2 inputs. Accounting maps Start to INTERNET_UPDATE, Stop to INTERNET_STOP, and the non-Start/non-Stop path to INTERNET_UPDATE; this includes A1.24 Alive handling. Disconnect/kill uses the configured external launcher command and provider RAS IP.
- ATD correction: both provider profiles now explicitly expose Start/Stop/Alive. Regression tests cover Alive support for both.
- This is source-derived behavior; Markdown audit text does not override the canonical archive.


### Concrete adapter batch — 2026-10-08
The source-traced pure provider boundaries have now been attached to ATD without introducing external side effects:
- Persistent LAN: `mac_ip` identity, persistent-lan marker, IP assignment disabled, Start/Stop native persistent-LAN actions.
- SER: `call_id` identity, SIP called-number and Digest extraction, Start/Stop call lifecycle actions.
- Asterisk: H323 identity plus source-defined `asterisk_multi_login` capability attribute.
- GnuGk: H323 identity plus source-defined `gnugk_multiple_login` capability attribute.
- MVTS: H323 conference identity.
- Quintum Tenor: H323 conference identity, single-session-H323 and disabled multi-login capability.
- MikroTik: NAS-Port identity, source-derived IP assignment and Start/Alive/Stop actions.
These adapters intentionally stop before SNMP/RSH/launcher/Asterisk Manager/H323/SIP external operations; those require concrete side-effect call-path tracing and integration fixtures.
PPPD remains open because the durable source evidence currently establishes only its `port` identity, which is not enough to infer the rest of its runtime behavior.
