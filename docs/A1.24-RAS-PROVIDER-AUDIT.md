## Source-derived runtime distinctions

### Internet RAS providers
The following providers maintain provider-specific online/accounting state and map RADIUS packets into the generic A1.24 user/session attributes rather than merely forwarding raw RADIUS counters:

- **MikroTik** — unique id is `port`; NAS-Port is used for the port key; Ethernet/Virtual/Wireless NAS-Port-Type changes IP-assignment behavior; Start initializes accounting state; Stop records final octets; Alive calculates byte-rate deltas and updates the online state.
- **BSAE** — unique id is `port`, port is User-Name, multi-login is explicitly false; Start/Stop/Alive are handled; IP learned from the Access-Accept is retained and reused for accounting; provider keeps per-port online and byte/rate state.
- **ChilliSpot** — unique id is `port`, port comes from NAS-Port, and `ip_assignment` is explicitly false; Start/Stop/Alive are handled, with Alive capable of re-online recovery; provider keeps online byte/rate state and has a provider-specific RADIUS Disconnect-Request path.
- **Cisco** — unique id is `port`; port normalization depends on Cisco/NAS port attributes; provider has separate internet and VoIP state, SNMP/RSH disconnect operations, and provider-specific byte/rate state; multi-login is explicitly false for the VoIP path.
- **Cisco VPDN** — uses Acct-Session-Id as the internet online key and has provider-specific interface discovery/kill behavior through RSH; online state has provider-specific stale-update handling.
- **PortMaster** — unique id is `port`, port comes from NAS-Port; provider uses SNMP for online/kill operations and keeps provider-side byte/rate state.
- **PortSlave** — unique id is `port`, port comes from NAS-Port; provider uses external launcher commands for listing/killing users and maintains provider-side accounting state.
- **Total Control** — unique id is `interface_index`, sourced from `USR-Interface-Index`; provider maps the interface index to NAS-Port and uses SNMP-derived IN/OUT counters.

### VoIP / telephony RAS providers

- **GnuGk** — VoIP-specific provider behavior; source-defined multi-login capability defaults false and is enabled only by the `gnugk_multiple_login` RAS attribute.
- **Asterisk** — VoIP handler exposes pre-authentication/authentication/authorization/call-end operations through the Asterisk manager; source-defined `asterisk_multi_login` defaults false and enables multi-login when nonzero.
- **Quintum Tenor** — VoIP provider keyed by `h323_conf_id`; maintains pre-auth usernames and online conference IDs; source sets multi-login false and `single_session_h323` true; Stop consumes the Quintum H323 disconnect cause.
- **MVTS** — VoIP provider keyed by `h323_conf_id`; source enables H323 authorization/accounting and remaining-time calculation, with provider-specific start/stop/alive processing.
- **SER** — SIP provider keyed by `call_id`; Start is tied to SIP INVITE and records the call id; Stop removes the call id; source maps Digest attributes and derives the called number from the SIP URI.
- **Cisco** — also contains a VoIP path keyed by H323 conference id in addition to its internet path.

### Persistent LAN

- **PersistentLanRas (plan.py)** is not a conventional RADIUS accounting provider. Source creates an internal `mac_ip` identity, marks the message `persistent_lan=True`, starts accounting, disables IP assignment, and maintains its own online/waiting lifecycle.

## Important parity consequence

The current ATD generic RADIUS runtime correctly models the common AAA/session/accounting boundary, but **full A1.24 RAS provider parity cannot be achieved by a single generic RAS boolean table**.

Provider-specific parity requires adapter behavior for:

1. identity/unique-id derivation;
2. input attribute extraction;
3. Start/Stop/Alive translation;
4. byte/rate counter semantics;
5. provider-specific IP assignment behavior;
6. provider-specific multi-login capability;
7. Disconnect/kill mechanisms;
8. VoIP/H323/SIP authentication and accounting;
9. provider-specific stale-online detection and update intervals;
10. provider-specific external SNMP/RSH/launcher integrations.

### Direct canonical-source verification — Cisco / Cisco VPDN — 2026-10-08
- Canonical files inspected directly from `Source of Truth/IBSng-A1.24.tar.bz2`: `IBSng/core/ras/rases/cisco.py` and `IBSng/core/ras/rases/cisco_vpdn.py`.
- Cisco Internet path: `unique_id="port"`; port is derived from `Cisco-NAS-Port` when present, otherwise from `NAS-Port-Type` + `NAS-Port`, with Async normalization.
- Cisco VoIP path: `unique_id="h323_conf_id"`; H323 conference ID is source-derived. VoIP explicitly sets `multi_login=False` and `single_session_h323=True`.

- Cisco disconnect/kill behavior is provider-specific SNMP-or-RSH; the source contains both paths and the SNMP kill path uses the Cisco interface mapping.
- Cisco VPDN uses `unique_id="acct_session_id"`, consumes Acct-Session-Id and Cisco-NAS-Port during authentication, handles Start/Stop/Alive, and kills through RSH after discovering the user's interface. Its source-defined disconnect strategy is therefore `rsh-interface`.
- ATD correction: `provider_session_id(..., service="voip")` now returns Cisco's H323 conference identity while preserving Cisco Internet identity as `port`.
- Regression coverage was added for both Cisco Internet and Cisco VoIP identity paths.
- Source-audit branch/workflow was isolated and is not part of `main`.

### Direct canonical-source verification — PortMaster / Total Control SNMP disconnect — 2026-10-09

The canonical archive SHA-256 was verified during this inspection before extraction. Exact call paths in core/ras/rases/portmaster.py and core/ras/rases/total_control.py establish:

- **PortMaster** uses SNMP v1 over UDP/161. Source defaults are community public, timeout 10, retries 3. killUser() reads the provider port, computes the IF-MIB interface index as int(port) + 2, and performs one SNMP SET on .1.3.6.1.2.1.2.2.1.7.<index> with ASN type i and value 2 (administrative down).
- **Total Control** uses SNMP over UDP/161, defaults community public, timeout 10, retries 3, and SNMP version 1. killUser() takes the source-derived interface_index and performs two ordered SETs on .1.3.6.1.2.1.2.2.1.7.<interface_index>: first integer 2 (down), then integer 1 (up). The order is part of the source behavior and must not be collapsed into a single SET.
- Total Control's interface_index is the existing source-traced USR-Interface-Index VSA (vendor 429, sub-attribute code 0x9843, integer, USR-specific 32-bit encoding).

ATD now has transport-neutral request builders for both exact operations and wires them through the corresponding provider adapters. The builders validate the target IPv4 address, numeric source identity and SNMP settings, preserve Total Control's down-then-up ordering, and snapshot the resulting parameters. They do not execute SNMP network I/O. A real SNMP transport and live-device interoperability tests remain separate work; no claim of end-to-end provider completion is made here.

### Canonical-source correction — PPPD kill path and Quintum Tenor strategy — 2026-10-09

A fresh extraction of the canonical archive (SHA-256 verified) corrected two earlier audit conclusions:

- **PPPD does have a concrete kill path.** In core/ras/rases/pppd.py, PPPDRas overrides killUser() and calls the configured pppd_kill_port_command through the script launcher with arguments ordered as [RAS-IP, port]. The source default command is %spppd/kill using IBS_ADDONS. PPPD therefore has the source-derived launcher disconnect strategy; its prior “identity only / insufficient kill-path evidence” status is superseded.
- **Quintum Tenor does not define a killUser() override.** It inherits the base Ras.killUser(), which is a no-op. Quintum-h323-disconnect-cause is consumed when translating a VoIP accounting Stop into disconnect_cause; it is accounting metadata, not a provider-side H323 kill operation. The previous h323-cause disconnect strategy was incorrect and is removed.

ATD now exposes a PPPD launcher request builder that requires the configured command explicitly and preserves the source argument order (RAS-IP, port). It creates an immutable transport-neutral envelope only; the launcher is not executed. Quintum Tenor remains source-supported for H323 identity/accounting semantics but has no generic external disconnect strategy.

This correction supersedes earlier statements in this audit that listed Quintum Tenor H323 as an external disconnect strategy or described PPPD as having only identity evidence.


## Source-derived Cisco VPDN and MikroTik RSH builders — 2026-10-09

The checked-in canonical archive was re-hashed on a clean GitHub Actions runner before extraction. Correct SHA-256: `c7117a6a2fd252aa9b8149a1ee6606f9320888da347ee4f839614bb9349d18a8`. An earlier handoff checksum was a transcription error; archive bytes were not changed.

### Cisco VPDN

- Configured RSH wrapper attribute: `cisco_rsh_command`, source default `%scisco/rsh_wrapper` using `IBS_ADDONS`.
- RSH client target: the RAS IP; maximum concurrent connections defaults to 3.
- Interface discovery calls `show caller user <username>`, parses the caller list, and if a remote IP is available selects the matching username + remote-IP row. The resolved interface is disconnected with the exact command `clear interface <interface>`.
- ATD builder represents only that final command and requires the interface to have been resolved by the caller. It does not claim to implement source lookup/parsing yet.

### MikroTik

- RSH client target: RAS IP; configured wrapper attribute `mikrotik_ssh_wrapper`; source uses three concurrent connections.
- The wrapper argument order is `[mikrotik_ssh_username, mikrotik_ssh_password, command]`.
- For exact `NAS-Port-Type == "Wireless-802.11"`, command is `/ip hotspot active remove [/ip hotspot active find user=<normal_username> address=<client_ip>]`.
- Otherwise command is `/ppp active remove [/ppp active find name=<normal_username> address=<client_ip>]`.
- ATD implements both request variants as immutable envelopes. Because A1.24 interpolates values into an unquoted RouterOS command, the builder rejects username tokens outside a conservative safe allowlist rather than inventing quoting/escaping behavior.

These builders do not execute the configured wrapper and do not prove real-device interoperability. The caller must supply source-derived RAS IP, client IP, normalized username, NAS-Port-Type and configured wrapper credentials. Frozen authentication, MultiLogin, attribute inheritance, persistence and accounting-core behavior were not modified.

### Cisco VPDN interface lookup completion note

ATD now builds the exact `show caller user <username>` RSH request and has a pure parser matching the source regex (`User: (.+?), line (.+?), .+? remote (IPv4)`, multiline + dot-all). With a remote IP supplied it selects the row matching both username and remote IP; without one it selects the first parsed interface. The disconnect request builder remains a separate step. End-to-end execution/orchestration of lookup → parse → clear-interface is not yet wired to a real RSH transport.

## Cisco generic disconnect branch completion — 2026-10-09

The canonical Cisco provider source confirms that `cisco_kill_use_snmp` defaults to 1 and selects the kill mechanism:
- **SNMP branch (default):** refreshes the IF-MIB interface-description map from walk OID `.1.3.6.1.2.1.2.2.1.2`, maps the source port description to its numeric ifIndex suffix, then performs SET `.1.3.6.1.4.1.9.2.1.76.0`, ASN integer, value equal to that ifIndex. SNMP defaults: community `public`, timeout 10, retries 3, UDP/161, version `2c`.
- **RSH branch (only when configured false):** `Async...` ports use the source regex `(Async[0-9/]+)` and command `clear line <port-without-Async-prefix>`; `Serial...` ports use `clear interface <port>`. Other port families return failure/no request; no command is guessed.
- ATD now exposes the source interface-description → ifIndex resolver and the configured SNMP/RSH request builder. The generic strategy remains intentionally ambiguous until the caller supplies source-derived config and, for SNMP, the resolved index.
- Builders emit immutable request envelopes only. SNMP/RSH transport execution, interface-map refresh, error handling and live Cisco integration remain open.


## Transport implementation checkpoint — 2026-10-09

- Cisco SNMP branch now has a bounded IF-MIB ifDescr GETNEXT walk, a port-description-to-ifIndex resolution step, and a service that executes the source-derived Cisco SET only when the requested port is found.
- SNMPv1/v2c SET transport validates response peer, request ID, version/community, OID, response ASN type and agent error status; timeout/retry bounds are explicit. Total Control's ordered down/up SET reports partial completion on failure.
- PPPD/PortSlave have a shell-free launcher transport restricted to these audited provider families, with absolute executable path, explicit argument array, timeout and non-zero exit reporting.
- Full CI is green on commit `b576ece6547ca9a29bc24602b994c35aecd52329`; unit suite 450 passed, 2 skipped, 2 warnings.
