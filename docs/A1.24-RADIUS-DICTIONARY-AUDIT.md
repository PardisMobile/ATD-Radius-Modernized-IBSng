## USR vendor dictionary

A1.24 also ships a large USR vendor dictionary under vendor id 429. It includes provider-specific channel, modem, call, VPN, routing, multicast, interface-index and HARC/RMMIE attributes. These are relevant to providers such as Total Control and should be represented through a vendor-aware dictionary rather than guessed as ordinary standard attributes.

## Compatibility rule

The existing ATD codec supports only a subset of these names. Unknown attributes currently use the generic `Attr-N` escape for numeric wire attributes, but that is not equivalent to a source-derived dictionary.

Next implementation work:
1. add a source-derived wire dictionary catalog;
2. add standard missing attribute names/types to the codec;
3. add SIP/Digest attributes needed by SER/MVTS;
4. add vendor-aware USR VSA support only where provider behavior actually consumes those attributes;
5. add enum/value translation fixtures from the canonical dictionaries.

This audit is source evidence; it does not claim the above attributes are all required for every ATD deployment.

Direct extraction of the canonical A1.24 dictionary files verified the SIP types and the core/SIP number collision:

- 110..119 Sip-User-ID/Realm/Nonce/Method/Digest-URI/Nonce-Count/QOP/Opaque/Response/CNonce — string
- 208 Sip-URI-User — string
- 210 Sip-Req-URI — string
- 211 Sip-Group — string
- 212 Sip-CC — string
- 213 Sip-RPId — string
- 225 SIP-AVP — string
- 206 Digest-Response and 207 Digest-Attributes — string
- Internal Digest-Realm through Digest-User-Name use 1063..1072 and are not ordinary one-octet wire attributes.
- dictionary.ser also confirms the SIP accounting/auth usage of these attributes.

Important compatibility constraint: A1.24's SIP dictionary reuses numeric codes that the core dictionary uses differently (for example SIP 101 versus core Error-Cause 101). Therefore these cannot be added as a global name->number mapping without a dictionary/provider context boundary. The correct next implementation is a context-aware SIP/SER dictionary catalog and codec path, with explicit tests, rather than silently changing the core mapping.

The canonical USR dictionary is vendor 429 and includes a large set of USR attributes with mixed string/integer/date types. No global USR catalog was added in this checkpoint because provider consumption must determine which attributes are required and the VSA encoding must preserve the source-specific vendor format.


## Core wire-type audit correction — 2026-10-09

A direct re-check against the canonical `IBSng/radius_server/dictionary` found that the prior codec correction was wrong for two attributes. The source declares `Framed-IPX-Network` (attribute 23) as `ipaddr`, and `Login-LAT-Port` (attribute 63) as `integer`. The codec has been corrected to preserve those exact source dictionary types: Framed-IPX-Network uses the four-octet IP-address path, while Login-LAT-Port uses uint32 network-order encoding. Regression tests assert the actual wire type, length and payload for both attributes.

The source dictionary also confirms `Framed-Routing`, `Acct-Authentic`, `Acct-Link-Count`, `Acct-Input-Gigawords`, `Acct-Output-Gigawords`, `ARAP-Zone-Access`, and `ARAP-Security` are integer attributes. Integer encoding validates unsigned 32-bit quantities (0..4294967295), rejects bool/float coercion and out-of-range values with `RadiusCodecError`. Directly extracted A1.24 VALUE entries are now covered for Framed-Routing, Acct-Authentic, Acct-Status-Type (including the source alias `Alive=3` and tunnel values), and every NAS-Port-Type label. The wire decoder uses a canonical label for duplicate value aliases; for example, wire value 3 decodes as `Interim-Update` even when `Alive` was supplied for encoding. This remains a partial dictionary catalog, not complete parity for every core/SIP/USR VALUE entry.

This correction explicitly supersedes the earlier paragraph that classified Framed-IPX-Network as an integer and Login-LAT-Port as a string.
