# A1.24 adoption preflight (read-only)

Install the project and run:

```sh
atd-radius-a124-preflight --archive /path/to/IBSng-A1.24.tar.bz2 --dsn "$ATD_DATABASE_URL" --output a124-preflight.json --fail-on-drift
```

The command is strictly read-only. It pins the canonical archive SHA-256, reads the source schema/functions/initial data/definitions from the archive, and reports missing/extra native tables and columns, explicit indexes, sequences, function names and argument signatures, baseline definition values, and core system-admin/state markers. It also inventories target-side constraint definitions, non-internal triggers, rewrite rules, and sequence configuration/current values as JSON evidence for semantic review. It can write a JSON report to a file. It does not create or alter any database object.

**A clean report is not an adoption authorization.** Column type/default/nullability normalization is conservative and may flag equivalent expressions. Constraint and trigger definitions plus sequence state are collected as target-side evidence. The two source-defined A1.24 deletion-protection rules are compared for presence, event, table, and normalized predicate. Canonical A1.24 stored function bodies are decoded and compared using SHA-256 digests keyed by function name and argument types. The two source-defined serial sequence ownership mappings are compared, and target-owned sequences are checked so their last_value is not behind the maximum stored value in the owned column. Other constraint/trigger semantics are not yet compared against canonical definitions; plugin objects, all row data, sequence semantics for manually advanced/unowned sequences, and backup/restore fidelity are also not fully verified. Do not stamp migration versions or cut over production based on this report alone. Full import/adoption requires these checks plus a verified restorable backup and a reviewed, transactional ledger-baseline procedure.
