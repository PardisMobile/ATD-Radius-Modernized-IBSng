# A1.24 Attribute Behavior Audit

This audit is based on the source archive stored at Source of Truth/IBSng-A1.24.tar.bz2.

## Confirmed database structures

- user_attrs(user_id, attr_name, attr_value) with primary key (user_id, attr_name)
- group_attrs(group_id, attr_name, attr_value) with primary key (group_id, attr_name) and index (attr_name, attr_value)
- ras_attrs(ras_id, attr_name, attr_value) with primary key (ras_id, attr_name) and unique index (ras_id, attr_name)

## Confirmed runtime behavior

### User

UserLoader.getUserAttrsByUserID() combines the generic user_attrs collection with normal-user, VoIP-user, persistent-LAN and caller-ID data before constructing UserAttributes.

### Group

GroupLoader loads group_attrs by group_id and converts each row into an attribute dictionary. Group actions expose change/delete operations through the Attribute Manager and database function calls.

### RAS

RasLoader loads ras_attrs by ras_id and passes the resulting attribute dictionary into the RAS implementation. ras_actions.py implements update/add/delete behavior and reloads the RAS after changes.

## Compatibility requirements

1. Preserve attribute names and string values exactly.
2. Preserve the one-value-per-(owner, attr_name) A1.24 constraint for these three tables.
3. Preserve add/update/delete semantics rather than treating attributes as an append-only bag.
4. Preserve lookup by attribute name/value because the A1.24 schema indexes it for users/groups.
5. Preserve the fact that user attributes are merged with subtype-specific and auxiliary user data during load.
6. Preserve RAS attribute reload behavior after mutation.

## ATD implementation boundary

ATD should expose one modern attribute service/repository while retaining explicit adapters for user, group and RAS ownership. The adapter must preserve A1.24 persistence constraints and behavior. Protocol consumers must use the resolved attribute state rather than bypassing the service.

## Generic user attribute mutation — source trace, 2026-10-10

Canonical source paths reviewed:
- `core/user/user_handler.py::updateUserAttrs`: requires administrator auth, loads requested users, calls `admin_obj.canChangeUser`, then delegates to the action manager.
- `core/user/user_actions.py::updateUserAttrs` and `updateUserAttrsQuery`: builds change/delete operations through the Attribute Manager, executes the combined query, broadcasts changed user IDs, then invokes each updater's `postUpdate`.
- `core/user/attribute_manager.py::getAttrUpdaters`: only registered handlers produce updater objects; unknown names do not become generic writes.
- `core/user/attr_updater.py::useGenerateQuery`, `_changeUserAttr`, `_deleteUserAttr`: the generic updater upserts or deletes `user_attrs`; with `USER_AUDIT_LOG` enabled it records old/new values using the `_NOVALUE_` sentinel and native `insert_user_audit_log` function.
- `core/user/plugins/comment.py`: `name`, `comment`, and `phone` use this generic updater and define no additional validation or `postUpdate` side effect.
- `core/user/plugins/lock.py`: generic upsert/delete; presence of `lock` means locked.
- `core/user/plugins/multilogin.py`: converts to integer and enforces 0–255, then uses the generic updater.
- `core/user/plugins/session_timeout.py` and `idle_timeout.py`: convert to integer, then use the generic updater.
- `core/user/plugins/owner.py::OwnerNameAttrUpdater`: updates `users.owner_id` (not `user_attrs`), conditionally checks `CHANGE USERS OWNER`, and audits under attribute name `owner`.

ATD's mutation slice exposes `PUT /api/v1/users/{username}/attributes` for seven source-traced handlers: `name`, `comment`, `phone`, `lock`, `multi_login`, `session_timeout`, and `idle_timeout`. `PUT /api/v1/users/{username}/owner` separately implements `owner_name` because the A1.24 updater changes `users.owner_id` rather than `user_attrs`. It requires `CHANGE USER ATTRIBUTES` and the native `GET USER INFORMATION` dependency/owner scope, locks the target user row, preserves insert/update/delete and native user-audit semantics, and commits the ATD operational audit in the same transaction. Unsupported/specialized names are rejected rather than written directly. This is a deliberately narrow slice, not full user-attribute parity.

CI passed on code/test checkpoint `60237946c885c8f541480f9b2428f253950f7772`: 649 tests passed on both Python 3.11 and 3.12 (2 warnings each), with compile, Ruff, PHP syntax and PostgreSQL integration. Further source-vs-ATD compatibility fixtures are still required before claiming parity. Specialized attributes (credentials, caller IDs, IP allocation, charges, expiration, group reassignment, VoIP, RADIUS attributes, etc.) remain blocked until their own validation, storage, and post-update behavior are implemented.
