# A1.24 Runtime Consumer Map — RAS, IP Pool, User Loading

Canonical source: Source of Truth/IBSng-A1.24.tar.bz2

## RAS loading

`core/ras/ras_loader.py` loads active RAS IDs from `ras`, then loads:

- `ras` basic record
- `ras_attrs` as `{attr_name: attr_value}`
- `ras_ports` keyed by `port_name`
- `ras_ippools` ordered by `serial`

The loader constructs the RAS implementation through `ras_main.getFactory().getClassFor(ras_type)` and registers the RAS as a RADIUS remote host using its IP and secret.

## RAS mutation

`core/ras/ras_actions.py` performs update/insert/delete operations against `ras_attrs`. The source path also triggers RAS reload behavior after attribute changes. ATD must preserve this lifecycle; persistence alone is insufficient.

## IP pool runtime

`core/ippool/ippool.py` uses a container with explicit free/used state and an RLock. Allocation removes the first free IP and appends it to used state. Packet assignment writes `Framed-IP-Address` and `Framed-IP-Netmask=255.255.255.255`. Explicit IP use removes it from free state and rejects an already-used address.

## User loading

`core/user/user_loader.py` builds a complete user attribute dictionary by merging, in source order:

1. `user_attrs`
2. `normal_users`
3. `voip_users`
4. persistent-LAN attributes
5. caller-ID attributes

The same logical merge is implemented for bulk loading. This means ATD cannot treat `user_attrs` as the entire user attribute source.

## Group loading

`core/group/group_loader.py` loads generic group attributes from `group_attrs` and combines them with the group model before user/group policy evaluation.

## ATD implementation requirement

The modern implementation should keep these source boundaries explicit:

- repository/persistence adapters for each A1.24 table;
- domain aggregation matching source merge order;
- runtime reload hooks for mutable RAS state;
- deterministic IP-pool allocation semantics;
- parity fixtures that compare source behavior rather than only schema shape.

Status: source-mapped. Automated cross-implementation parity remains pending.
