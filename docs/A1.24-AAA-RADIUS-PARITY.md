## MultiLogin source recheck — 2026-10-09

The canonical `core/user/plugins/multilogin.py` checks the user limit first, then rejects a second instance when `False` is present in the accumulated `multilogin_allowed` list. ATD previously checked only the incoming request's RAS capability. The source-driven correction now:
- resolves VoIP policy branches for Asterisk/GnuGk/MVTS/SER/Quintum Tenor RAS types;
- stores the RAS MultiLogin capability as internal `SessionState` metadata (not a RADIUS attribute or connection-log detail);
- carries that value into active-session policy views; and
- rejects a second login if either the current RAS or any existing active session disallows MultiLogin, after applying the user `multi_login` limit first.

This is still bounded by the runtime session source: ATD's active-session registry is populated by Accounting Start/Interim events, so an accepted login that has not emitted accounting yet is not represented in that in-memory view. End-to-end timing parity for that edge remains open.


## MS-CHAP and MPPE source recheck — 2026-10-09

A1.24's password plugin passes `normal_username` and `normal_password` into `checkMSChap2Password` and AuthenticatorResponse generation. ATD now uses the canonical username returned by `normal_credentials` when available. The original MS-CHAP helper converts Python 2 source bytes to UTF-16LE by interleaving each byte with a zero byte; ATD now mirrors that for UTF-8 database strings while retaining the RFC ASCII test vectors. The original plugin's `MS-CHAP2-Success` begins with a raw one-byte identifier; ATD now carries it as bytes to avoid UTF-8 expansion for high identifier values.

The original packet codec applies RADIUS `PwCrypt` to `MS-CHAP-MPPE-Keys` and uses salt + RADIUS-secret encryption for `MS-MPPE-Send-Key`/`MS-MPPE-Recv-Key`. ATD's codec has matching encryption paths. Non-ASCII password parity remains dependent on confirming the source database connection charset; live NAS interoperability is not yet validated.


## Non-ASCII MS-CHAPv2 AuthenticatorResponse parity — 2026-10-23

The AuthenticatorResponse path now uses the same A1.24 byte-wise `str2unicode` password conversion as NT-response verification and MPPE derivation. This preserves the RFC 2759 ASCII vector while avoiding a divergent direct Unicode-to-UTF-16LE conversion for non-ASCII database passwords. Regression coverage derives the expected digest from the source-compatible byte conversion. Database/client charset assumptions and live NAS interoperability remain separate release gates.


## MultiLogin policy consolidation — 2026-10-23

Centralized the A1.24 ordering in session_policy: reject at the configured user instance limit first, then reject a second instance if either the incoming RAS or any existing session's RAS explicitly disallows MultiLogin. The AAA adapter now normalizes false-like RAS capability values consistently (False, 0, case-insensitive false, and surrounding whitespace) and maps domain reasons to the established API/AAA rejection codes. Added regression coverage for precedence, incoming and existing RAS restrictions, and the all-RAS-allow case. The durable Access reservation/cross-worker lifecycle remains a separate integration boundary.
