# A1.24 AAA/RADIUS Parity Boundary

Canonical source: Source of Truth/IBSng-A1.24.tar.bz2

ATD now has explicit domain boundaries for the two core runtime stages:

1. Ordered AAA/plugin evaluation with terminal accept/reject/challenge decisions.
2. RADIUS access request/response mapping while preserving identifier and authenticator context.

These are domain boundaries, not a claim that a production UDP RADIUS server is complete.

The remaining protocol work includes packet encoding/decoding, authenticators, duplicate-request handling, dictionaries, NAS client validation, Access-Request dispatch into the full A1.24 plugin set, Accounting-Request lifecycle, Accounting-Response handling, CoA/Disconnect behavior and end-to-end integration tests.

Status: **domain boundary implemented; protocol/runtime parity pending**.
