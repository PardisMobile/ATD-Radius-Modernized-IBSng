# A1.24 Session Concurrency and Runtime Ownership Audit

Date: 2026-10-10
Repository: `PardisMobile/ATD-Radius-Modernized-IBSng`
Canonical source: `Source of Truth/IBSng-A1.24.tar.bz2`

## Confirmed in ATD

- `src/atd_radius/main.py::_start_radius_servers` creates one `NativeRadiusRuntimeState` and one `NativeRadiusPacketHandler`; the Authentication and Accounting UDP servers use that handler from separate daemon threads.
- `NativeRadiusPacketHandler.__call__` builds packet-scoped database services but reuses the process-local `state.sessions` registry.
- `SessionRegistry` mutates its dictionary and each `SessionState` without a lock. Operations such as lookup-then-start, update-then-stop, and matching-then-disconnect are multi-step operations.
- `AccountingSessionService.apply` composes registry and persistence mutations without an operation-wide synchronization boundary.
- `src/atd_radius/api/app.py` is constructed independently from the state created in `main.py`. The current admin API cannot authoritatively query or reserve the UDP runtime's live session state.
- The default `uvicorn.run(app, ...)` call does not configure multiple workers, but external ASGI launchers may use a different process topology. An in-memory registry cannot provide cross-process session truth.
- Connection history in PostgreSQL is not an authoritative replacement for active runtime state.

## Risk

Concurrent Accounting Start/Interim/Stop packets can interleave registry and persistence steps. Administrative deletion or disconnect cannot be made safe merely by checking the process-local registry from an unrelated API process. PostgreSQL advisory locks alone would not make other processes' in-memory session records visible.

## Safe implementation sequence

1. Add synchronization around compound registry/session lifecycle operations, with deterministic concurrency tests for duplicate Start, Interim-vs-Stop, and matching-vs-disconnect.
2. Define a single shared runtime owner for API and UDP when running in one process, with explicit startup/shutdown wiring and tests.
3. Define and enforce supported deployment topology. If multi-process operation is supported, introduce a durable, authoritative cross-process active-session/coordination design rather than pretending the in-memory registry is shared.
4. Only then implement native A1.24 online-user and disconnect flows with authentication/permission checks, source-compatible target resolution, correct ordering, and audit side effects.
5. Implement user deletion after active-session safety, complete A1.24 dependent-table inventory, transactional credit refund/ledger/deposit/IAS/audit handling, and post-commit effects are tested.

## Current decision

No user-deletion endpoint or RAS Disconnect endpoint is added by this audit. Do not infer online status from `connection_log.logout_time IS NULL`. Keep the A1.24 PostgreSQL schema unchanged unless a documented compatibility decision justifies a migration.

## Verification

This is an audit/design record, not a code change. The next code increment must add tests first and run the full CI matrix before any behavior is marked verified.
