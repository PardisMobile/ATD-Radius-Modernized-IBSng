# A1.24 RADIUS Dispatch Boundary

ATD currently has a domain/runtime dispatcher covering the major protocol families required by the current A1.24 parity work:

- Access-Request → AAA plugin pipeline → Access-Accept/Reject/Challenge
- Accounting-Request → typed accounting event + Accounting-Response
- Disconnect-Request → live session selection and termination
- CoA-Request → live session selection and supported authorization update

## Current implementation boundary
The codec/runtime includes:
- Access and Accounting wire encoding/decoding.
- PAP User-Password RFC algorithm.
- Accounting-Request authenticator verification.
- RFC 5176 Disconnect/CoA Request-Authenticator verification.
- Optional Message-Authenticator verification for control requests.
- Message-Authenticator emission on control responses when requested.
- Dynamic authorization attribute registration for the current control path.
- Duplicate request identity and expiry support.
- Native runtime composition through RadiusRuntimeHandler.
- Registry-backed session control with source-derived RFC 5176 selector validation and error causes.

## Session control
The current registry supports matching by the implemented NAS/session identifiers and applies all supplied supported selectors conjunctively. Disconnect stops all matching active sessions. CoA currently changes Filter-Id and NAS-Filter-Rule.

This remains a runtime boundary, not a claim of complete A1.24 RADIUS parity. PostgreSQL-backed session/online persistence, complete RAS provider behavior, full authentication protocol coverage, full attribute dictionary coverage and complete accounting/connection-log persistence are still integration/parity work.

## Runtime and verification correction — 2026-10-12

The earlier lines above saying the latest main HEAD had no workflow run and that complete accounting/connection-log persistence was still unintegrated are historical and superseded. The current Accounting-Request production path is composed by `NativeRadiusPacketHandler` and `RadiusRuntimeHandler`, applies session events, writes native connection history through `NativeAccountingPersistence(ConnectionLogRepository(conn))`, and performs the source-backed bandwidth snapshot partial integration. Full CI on code/test HEAD `f97af48b94204ac2e7d6065d522c29d2583dc76e` passed 694 tests on Python 3.11 and 3.12 (2 warnings each); full and Python-only CI also passed on docs checkpoint `f87a63cf46c6b271d6efdcc2a7d80af2d649c760`.

Important distinction: packet-level RFC 5176 Disconnect/CoA decoding, validation and registry session matching exist, but that is not equivalent to A1.24's provider-specific online-session lifecycle or verified RAS-side termination. Admin-facing destructive actions remain unmounted until trusted session ownership, permission dependencies, provider operation, audit ordering and cross-process/restart truth are safe. Native connection-log wiring exists; exact source detail-field parity, durable active-session state and live-device interoperability remain open.


## IAS event REST slice — 2026-10-12

The IAS event reader/deleter now maps native `ias_event` fields and the six A1.24 `IASActions.TYPES` IDs. The REST adapter requires `HANDLE IAS EVENTS`, caps event pagination, uses parameterized SQL, and logs deletion operationally. PostgreSQL integration passes. This is not full XML-RPC compatibility: `getIASUserInfo`, `lockUser`, `lockAdmin`, and other native handler methods remain open.
