# A1.24 RADIUS Dispatch Boundary

ATD currently has a domain/runtime dispatcher covering the major protocol families required by the current A1.24 parity work:

- Access-Request → AAA plugin pipeline → Access-Accept/Reject/Challenge
- Accounting-Request → typed accounting event + Accounting-Response
- Disconnect-Request → live session selection and termination
- CoA-Request → live session selection and supported authorization update

## Current implementation boundary
The codec/runtime includes:
- Access and Accounting wire encoding/decoding.
- PAP User-Password RFC algorithm.
- Accounting-Request authenticator verification.
- RFC 5176 Disconnect/CoA Request-Authenticator verification.
- Optional Message-Authenticator verification for control requests.
- Message-Authenticator emission on control responses when requested.
- Dynamic authorization attribute registration for the current control path.
- Duplicate request identity and expiry support.
- Native runtime composition through RadiusRuntimeHandler.
- Registry-backed session control with source-derived RFC 5176 selector validation and error causes.

## Session control
The current registry supports matching by the implemented NAS/session identifiers and applies all supplied supported selectors conjunctively. Disconnect stops all matching active sessions. CoA currently changes Filter-Id and NAS-Filter-Rule.

This remains a runtime boundary, not a claim of complete A1.24 RADIUS parity. PostgreSQL-backed session/online persistence, complete RAS provider behavior, full authentication protocol coverage, full attribute dictionary coverage and complete accounting/connection-log persistence are still integration/parity work.
